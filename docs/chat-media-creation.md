# 聊天媒体创作工具

在助手的「本地工具」中启用「媒体创作」，并在设置的「媒体创作」中配置供应商和图像 / 视频模型。
聊天模型需要支持工具调用。配置会跟随现有的会话配置快照规则，已有聊天需要在该会话中启用工具。

这是 `1.0` 分支基于当前 `mediagen` 和媒体创作会话重新设计的实现。历史 `custom` 分支的生图工具仅作为交互参考，
没有引入它的旧生图服务、聊天模型配置、生成图库、定时任务或 Web 服务。

## 使用

- 文生图 / 编辑图片：要求助手生成实际图片；编辑时指定聊天中的图片。
- 文生视频 / 图生视频：要求助手生成实际视频，可指定图片作为首帧、尾帧或参考图，也可使用参考视频。
- 审批卡片展示模型、创作要求和参数；点击详情可核对参考素材及其角色。确认后才提交给供应商。
- 提交后卡片观察同一条数据库记录，持续显示准备、排队、生成、下载、成功或失败；离开聊天不会停止任务。
- 一次生成调用会在应用内等待到生成和下载结束，再将最终结果交回模型继续回复；等待期间不会每隔 20 秒请求模型查询进度。
- 同一条回复中反复查询同一任务时，只在最后一步显示完整任务卡片；之前的调用保留步骤、耗时和可点击的详情。
  出错、待审批或无法识别的结果保留独立提示，不合并不同任务，也不删除工具历史或模型上下文。
- 图片可预览，视频可播放。「打开媒体创作」进入对应会话，可使用原有的保存、分享、重新编辑和历史记录功能。

图像和视频共用三个工具：

| 工具 | 行为 |
| --- | --- |
| `media_generate` | 审批后按 `kind=image/video`、模型、提示词、参数和参考素材提交一次任务；同一次调用等待到生成和下载完成、失败或取消后返回最终记录及产出 |
| `media_task_read` | 读取当前聊天已有任务的结果；已结束的立即返回，进行中的在应用内等待到终态，不重新提交或取消任务 |
| `media_task_cancel` | 停止当前聊天任务的本地生成 / 等待，保留历史；需要审批 |

卡片上的「停止等待」是用户直接操作，效果与 `media_task_cancel` 相同。它不能保证取消供应商已经接收的任务，也不保证退款。

## 完成后继续回复

聊天工具通过数据库的记录变化等待结果，不设置 20 秒返回窗口，也不为等待进度重复请求聊天模型。
只有媒体服务将生成和结果下载处理到成功、失败或取消，工具才返回，随后代理继续下一次模型请求。
成功结果已包含实际产出，无需再调用 `media_task_read` 确认一次。

`media_task_read` 用于复用较早的产出或接回已有任务，界面名称为「读取创作结果」。工具参数仅保留 `record_id`；
传入 `wait_ms` 或其他额外参数会明确报错，不提供旧接口兼容或参数迁移。
供应商异步接口必需的后台查询仍由 `MediaCreationService` 处理，聊天模型不参与轮询。

停止聊天只取消当前工具的等待，后台媒体任务及记录继续保留；之后继续这条已批准调用会接回同一个记录，避免重复生成。
从媒体卡片停止任务则会结束等待并返回取消状态。删除任务会结束等待并报错，不会重新创建记录。
等待不占用提交锁，其他聊天仍可提交媒体任务；审批、参考素材检查和结果权限规则沿用现有实现。

## 与媒体创作的连接

- 只使用 `Settings.mediaGenerationProviders` 中的模型，沿用 `setting.capabilities(kind)` 的适配器能力。
  不使用旧的 `imageGenerationModelId`，不另建供应商或模型默认值。
- 图像与视频分别提供可用模型及参数目录。未实现的媒体类型不会出现在目录里；不支持的字段、重复首尾帧、
  首尾帧与参考素材混用等请求在审批前报错，不静默丢弃素材或参数。具体参数取值仍由供应商模型校验。
- 视频使用首尾帧 / 参考素材时，沿用现有媒体服务的素材上传配置；图像接口支持本地素材时直接传本地文件。
- 每个聊天对应一个持久化的媒体创作会话，使用相同 UUID，但位于独立的媒体会话表中，无需增加数据库列。
  不复用其他手动创作的空白草稿，也不改写它们的输入。
- 提交、上传、轮询、下载、通知、前台服务和恢复逻辑全部复用 `MediaCreationService`。
  记录和输出仍在 `media_creation` 下，沿用现有的备份与清理规则。
- 图片、视频参考来自当前聊天的上传或工具结果；模型使用稳定的引用 ID，不能直接指定本地路径或下载 URL。
  要复用较早的后台结果时，先读取该记录，让实际产出进入工具上下文。

## 请求与恢复

生成请求在审批前固定媒体模型、供应商配置摘要、参数、参考素材和记录 ID，不执行生成或上传。
批准后再次检查配置和素材是否改变；配置摘要不包含可还原的凭据，聊天中不保存 API Key。
新任务执行时持有提交时的供应商配置，避免后台读取到后来编辑的端点。

请求固定的记录 ID 用于恢复：聊天中断后恢复同一次已批准调用，会返回已经存在的记录，避免再次计费。
失败、拒绝、停止等待或未知状态不自动重试。应用进程退出时，是否能恢复供应商任务由原有媒体服务的任务 ID 规则决定。
同步接口中断且没有供应商任务 ID 时，不保证找回远端结果。

工具只允许读取 / 停止当前聊天对应的记录。图片引用最多 16 个，图片生成数量最多 4；
视频数量由当前适配器固定为单段。参数沿用媒体创作的字段名，例如 `resolution`、`aspectRatio`、`durationSeconds`、
`generateAudio`、`watermark` 和 `seed`，只向模型公开所选适配器支持的字段。

私有审批快照只用于应用存储和界面，不回传聊天模型。文字模型只收到结果状态；支持视觉的模型可收到实际图像。
当前聊天模型的模态声明不包含视频，视频保留给用户播放，不向模型宣称它已看过视频内容。
