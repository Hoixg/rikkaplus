# 本地图片生成工具说明与验证记录

更新日期：2026-10-04。

## 调用与提示词规则

`generate_image` 只在用户明确要求生成或修改实际图片时提交申请。分析截图、讨论图片、编写或润色绘画提示词不触发生图；用户要求清楚时直接准备完整申请，仅在关键要求缺失、冲突或参考图指向不明确时询问。

工具说明、系统提示和参数说明共同要求：

- 完整提示词整合用户给出的主体、风格、构图、用途和约束；保留图片内文字的原文，不擅自添加无关要求。
- 改图明确修改内容与需要保留的内容；指定图片必须传入对应引用 ID，多图按传入 ID 顺序说明各自用途，不混入无关历史图片。
- 参考图不可用时先等待用户恢复或重新选择，不能默默改成纯文字生图。
- 未指定数量和尺寸时保持 `count=1`、`size=auto`，沿用原有数量和尺寸限制。接口没有透明背景、遮罩、种子等独立参数，不能承诺这些控制或保证生成效果。
- 每次调用仍需用户审批。待审批期间不重复提交；拒绝、取消或失败后等待用户明确要求再次尝试，不自动改写、拆分或换参考图申请。工具错误与历史结果不是重试授权。
- 提交或批准请求不代表图片已经生成。按照返回的 `image_count` 报告实际结果；同时返回图片与错误时说明部分完成，不自动补图。
- 根据当前聊天模型的图片输入能力提示其视觉边界；不能查看图片内容的模型只能依据用户描述处理改图，不声称已检查图片或确认效果。

助手工具开关的中英文说明同步强调明确的生图或改图要求；参考图失效及已审批模型配置变化的内部错误、中英文文案均改为说明本次无法执行，并等待用户处理后明确要求再次尝试。

## 参考图目录与兼容性

系统提示末尾的裸 ID 列表改为 JSON 引用目录，每项仅包含：

| 字段 | 含义 |
| --- | --- |
| `id` | 原有稳定图片引用 ID，用于 `reference_image_ids` |
| `message_index` | 当前会话消息列表中的序号，从 1 开始，包括没有图片的消息 |
| `role` | 图片所属消息的角色，小写，例如 `user`、`assistant` |
| `image_index` | 该消息内非空图片的序号，从 1 开始，包含按顺序遍历的嵌套工具结果 |

目录按当前消息顺序生成。历史上下文变化可以改变消息序号，引用 ID 保持原有生成规则；只有实际非空图片计入图片序号。目录不包含图片 URL、文件路径、图片字节、提示词内容、工具 metadata 或审批内部配置。

定位目录与原有参考图收集共用一次遍历规则。公开参数名称、默认值、校验限制、`ChatImageReference`、`ImageToolRequest` 的序列化格式、审批快照及审批/执行回调保持原样；目录位置只用于模型提示，不写入快照。继续沿用原有审批交互与等待规则，不增加限时审批，也不修改其他工具或图片提供商的调用接口。

## 对话验收与限制

以下场景已核对工具说明、系统提示及相应参数/错误文案；尚未做真实模型对话验收：

| 场景 | 预期行为 |
| --- | --- |
| “画一只水彩风格的猫” | 直接准备完整生图申请，默认一张、自动尺寸，等待原有审批 |
| “帮我写一段画猫的提示词” | 返回文字提示词，不调用生图工具 |
| “分析这张截图” | 分析截图，不提交生图申请 |
| “将这张图的背景换成蓝色，人物保持不变” | 选中指定图片 ID，明确背景修改与人物保留；缺少引用时询问 |
| “第一张作为人物参考，第二张作为画风参考，合成一张图” | 按用户指定顺序选择两张图片并在提示词中说明各自用途 |
| 用户拒绝、取消或提供商失败 | 说明状态，等待用户明确要求再次尝试，不自动重新申请 |
| 返回部分图片并伴随错误 | 报告实际图片数量与部分完成状态，不自动补足数量 |
| 聊天模型不支持图片输入 | 依据用户描述申请，不声称看过输入图或确认生成效果 |

`adb devices` 没有连接设备，当前未进行设备上的聊天卡片、取消与真实模型调用验收。单元测试使用模拟提供商，不调用外部生图服务；它们验证目录与执行流程，不能证明真实模型必然遵循提示词。实际调用时机、澄清次数、拒绝后的新申请行为和生成结果描述仍需按上表进行对话验收。
