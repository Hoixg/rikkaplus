# 本地工作区共享环境

本地工作区默认共用 `filesDir/environment/linux` 中的 Linux 系统和系统工具。
创建时可以打开「独立环境」，使用 `filesDir/workspaces/<root>/linux`，环境需单独安装；模式创建后固定，重命名不改变模式。
每个工作区仍有自己的 `filesDir/workspaces/<root>/files` 项目目录及 `tmp` 临时目录，分别挂载到 `/workspace` 和 `/tmp`。
系统级安装的 Python、Node、Git 等可以复用；项目依赖建议放在项目目录，如 `.venv` 和 `node_modules`。

环境安装入口位于任一本地工作区的设置中，状态和下载进度按环境分组。新建共享工作区只创建项目及临时目录，已有共享环境可直接使用。
同一环境的安装请求串行化，独立环境之间可分别安装；普通安装发现所选环境已就绪就复用，明确选择重新安装时才替换环境。
下载、解压、验证 `/bin/sh` 和系统配置均在临时目录完成，之后通过重命名发布新环境；失败或取消保留原环境。
安装与所选环境中正在执行的本地命令互斥；重装共享环境关闭共享工作区的终端，重装独立环境只关闭它自己的终端，等待进程退出后再替换。同时阻止该组新终端启动。

SSH 工作区继续连接自己的远端，安装状态、命令执行、目录和交互式终端不使用本地共享环境。重装本地环境不关闭 SSH 终端。
删除共享工作区只删除项目目录和记录，不删除共享环境；即使删除全部共享工作区，下一次创建仍可复用。删除独立工作区同时删除它自己的环境。
文件备份包含项目文件与所选环境模式，不备份 Linux 系统、安装临时文件和缓存。

按用户要求，不提供旧环境迁移或多环境兼容。已有项目文件继续使用，新版共享环境需要首次安装一次。
旧版 `workspaces/<root>/linux` 可能仍占用空间。通过「设置 → 数据设置 → 存储管理 → 旧环境清理」手动检测，查看目录与估算占用后逐项确认删除。仅列出未在使用的旧 Linux 目录，包括未关联记录的遗留目录；保留当前共享环境、独立环境、SSH 工作区和项目文件区。旧 Linux 中的 `/root`、配置和已安装工具会一起删除，应先确认不再需要。
清理前重新校验当前工作区记录、目录边界和扫描时的文件元数据；旧目录发生变化或共享环境尚不可用时拒绝删除。扫描和删除均不跟随符号链接，不删除整个工作区，不自动迁移或合并环境，也不在启动时自动清理。
PRoot 可能在旧 Linux 中留下权限为 `000` 的挂载占位目录（如 `workspace`）。仅对已确认停用且位于清理边界内的真实目录，在打开前补足所有者读取和进入权限，删除时再补写权限；不修改符号链接指向的目录或受保护环境。权限处理后再记录元数据，避免一次扫描产生立即过期的预览。
数据库从 33 自动升级至 34，增加 `independent_environment` 布尔列，默认关闭。各本地工作区的就绪状态由所选环境决定，SSH 保留自身状态。旧版应用无法直接打开升级后的数据库。
