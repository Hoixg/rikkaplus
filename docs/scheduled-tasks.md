# 定时任务

`1.0` 的定时任务按当前架构重新实现。历史 `custom`（c 分支）仅作为使用场景参考，不导入其源码模块、旧任务、旧运行记录、审批 metadata、迁移链或 Worker 兼容层。

## 使用

入口：**扩展管理 → 定时任务**。顶部显示启用任务数与活动运行数。任务卡片展示名称、排程、助手、执行模型、下次执行时间和当前运行状态，保留启停开关、立即执行／取消本次和编辑；运行记录与删除放在卡片的「更多」菜单。点击卡片也可编辑。

列表使用单块卡片，名称与启停开关位于顶部，排程使用整行宽度，助手与模型为次要信息；本次运行状态与后续执行时间分别显示，避免运行时看不到下一次排程。不展示提示词预览，完整提示词在编辑页查看。运行记录使用独立底部面板，并与聊天工具详情共用运行状态、时间和说明组件。

编辑页使用现有 MD3 Expressive 组件及 CardGroup，按任务内容、时间安排、执行设置分组；执行方式和排程复用连接式选择按钮，助手与模型允许两行显示，执行时间以可编辑、可删除的时间块展示，提供「添加时间」入口；指定日期与可选日期范围按需设置。长提示词在编辑输入框内部滚动。聊天中的审批步骤只显示简要配置，点击步骤打开完整配置；提示词随详情页整体滚动，不再嵌套滚动。修改审批只展示新配置，不保存或展示旧提示词对比。

页面直接维护 `TaskDefinition` 状态，只在页面状态保存／恢复时序列化，避免每次输入与重组都往返编码 JSON。排程表单与日期／时间选择器集中在 `AutomationScheduleEditor`，任务卡片、运行记录面板独立；排程、模型及运行文案复用 `ui/components/automation`，聊天渲染器不再依赖管理页面。

任务运行期间也可编辑后续配置，本次执行继续使用运行快照。仅修改提示词等内容时保留未消耗的执行时间；修改排程时重新计算，间隔排程仍以原创建时间为锚点。编辑保存沿用数据库中的最新启停状态，不会把编辑期间已经执行完的单次任务重新开启。

- 排程：指定日期、每天、每周、固定间隔；间隔至少 15 分钟。指定日期、每天、每周均支持多个执行时间，同一任务可以设置 10:00 和 18:00。
- 「每天」会在每天的每个时间点各执行一次；「每周」会在选中星期的每个时间点各执行一次。每天/每周仍支持开始与结束日期。
- 「指定日期」仅执行所选日期的这些时间点，最后一个时间点消耗后停用。多个时间自动排序去重，至少保留一个时间；点击时间块修改，点击叉号删除。
- 新建聊天：每次独立创建聊天，继承助手设置及预设消息。
- 继续聊天：向所选助手的目标聊天追加提示词，使用执行时最新上下文。
- 继续聊天可开启「每次清空上下文和记录」，默认关闭。开启后，每次实际开始执行前删除目标聊天的全部旧消息、分支、压缩检查点及聊天建议，仅保留本轮记录；聊天 ID、标题、模型配置、系统提示词、工作区和文件夹归属保留。任务等待聊天空闲时不会清空，工具审批后继续本轮也不会再次清空。消息持久化和未引用附件清理沿用 ChatService 的现有逻辑。
- 重新生成：复用现有聊天分叉与附件复制逻辑，将所选用户消息及此前的上下文复制到新聊天，原聊天保留。
- 指定模型只对本次任务生效，不修改助手或目标聊天的默认模型。实际开始时保存模型 ID 和名称，审批后继续使用同一个模型，历史记录显示实际执行模型。

自动执行需要 Android 精确闹钟授权。没有授权时可以保存停用任务并立即执行；启停只控制后续排程，不取消正在进行的运行。任务级通知复用现有聊天通知系统，受应用与系统通知设置控制。

### 后台运行与权限

定时任务列表、编辑页右上角的设置按钮及**设置 → 偏好设置**共用“后台运行与权限”入口，授权完成后也可再次管理。

- 通知权限：复用现有权限请求与说明组件；已授权时进入系统通知设置，同时提供现有应用内生成通知设置入口。
- 精确闹钟：显示真实授权状态并进入系统授权页，返回后重新读取状态、重建排程。
- 电池优化：读取系统真实豁免状态，进入标准电池优化列表，由用户将本应用设为不优化；不新增直接申请豁免的权限。
- 自启动与后台活动：尝试对应厂商的系统入口，打不开时回退应用详情，不依赖 resolveActivity 推断可用性。状态不标成“已授权”，需要用户在系统中确认。
- 应用系统设置：直接进入本应用详情，用于确认后台电池限制等厂商选项。

页面回到前台时刷新状态。未授权通知、电池豁免或自启动不会禁止手动运行，也不自动修改任何系统设置。

系统入口依据 [Android Settings 文档](https://developer.android.com/reference/android/provider/Settings) 与 [Doze/应用待机文档](https://developer.android.com/training/monitoring-device-state/doze-standby)；厂商入口是否可用仍需对应手机验证。

## 执行与恢复

复用 AlarmManager 发送到期事件，短期前台服务只负责分发，生成及前台生命周期由现有 ChatService 和 ChatGenerationForegroundService 管理。仅实际生成期间持有带超时的 CPU 唤醒锁，等待审批和空闲时释放；不新增聊天生成器或全天保活。

- 一个任务最多有一个活动运行；一个聊天最多由一个任务占用。
- 目标聊天正在生成或压缩上下文、有待审批工具或有排队用户消息时，任务等待，用户消息优先。压缩与生成共用会话任务槽，手动压缩、回复结束后的自动压缩和工具步骤间的自动压缩均不允许定时任务抢占。
- 等待期间不持有生成服务。聊天生成结束、应用回到前台或后续检查闹钟会重新尝试。
- 到期事件在事务中核对任务版本和到期时间，消耗该时间槽后推进排程，重复投递不重复执行。
- 手动执行不改变未来排程；重复执行请求使用同一个 request_id 时返回原运行。
- 任务仍在执行时遇到下一时间槽，将该次记录为跳过。
- 累计生成时间最多 10 分钟，等待空闲与等待审批不计时。达到模型步骤上限记为失败。
- 等待工具审批时保存运行与模型快照，沿用普通审批，没有定时任务专用倒计时。
- 进程中断的 RUNNING 记为失败，不自动重复发送；QUEUED 可继续等待，APPROVAL 可从聊天恢复。
- 开机、应用升级、时钟或时区变化及重新获得权限后重建闹钟。Android 强行停止、厂商后台限制仍可能阻止准时执行，需要实机确认。

## 存储

在本分支主数据库新增两张独立的新表，随现有数据库备份机制保存：

- `automation_task`：定义、启用状态、配置版本、下次执行时间。
- `automation_run`：执行时的定义快照、实际模型、聊天 ID、状态、累计生成时间及结果说明。

任务与运行通过外键关联；删除任务删除其运行记录，不删除聊天。保留全部活动运行和最近 20 条结束记录。唯一索引保护任务和聊天的活动占用。

多个时间直接存入既有任务定义 JSON：每天/每周使用 `timesMinutes`（当天零点后的分钟数），指定日期使用 `atTimes`（绝对毫秒时间戳）。原有单时间任务继续使用 `timeMinutes` / `at`，未设置数组时按原时间执行。不增加数据库、数据表、列或迁移。指定日期的绝对时间不会因时区切换变成其他时刻；每天/每周继续跟随当地日历。

这两张表在主数据库 `32→33` 时加入，现有聊天等数据保留。当前主库 schema 为 35，后续工作区和消息索引迁移没有重建任务表；局部编辑也不改动 schema。这不是旧 c 分支数据库的迁移或兼容方案。

## AI 管理

使用 `scheduled_task` 一个工具，查询操作为 `list/get/options/history`。`create/update/set_enabled` 只修改聊天内草稿，不审批、不写正式任务或重建闹钟。
同一任务可以连续改名称、时间、模型和多段提示词，全部整理好后只调用一次 `save(id)`，沿用现有工具审批展示完整最终配置，批准后一起保存。
删除、立即执行和取消运行仍是各自独立的最终操作，沿用原有审批。

查询现有任务直接调用 `list`，按需使用返回的任务 ID 调用 `get/history`，不以会话查询或 `options` 为前置步骤。
列表直接从任务表按当前助手筛选，并返回执行方式、关联会话 ID 和模型覆盖 ID；不会为此读取聊天内容。

`options` 默认只生成任务 / 执行请求 ID，并返回当前会话 ID。选择模型覆盖时显式传 `include_models=true`，
选择其他目标会话时显式传 `include_conversations=true`；这两份列表默认不加载。
只有为重新生成选择用户消息时才传 `target_conversation_id`，按原有规则校验助手归属和当前分支。
工具卡片分别显示「查询任务列表」「查看任务详情」「查看运行记录」「准备任务操作参数」、
「选择目标聊天」或「查询可选模型」，并按查询、编辑、保存、执行和取消使用不同图标，避免把不同操作都标为查询定时任务。

聊天工具展示统一由 `AutomationToolPresentation` 从当次调用的参数、输出及草稿 metadata 解析。列表展示最多三个任务的摘要，运行记录展示最近一条，点击步骤查看全部；不直接向用户展示 JSON。中间草稿编辑和参数准备仅保留步骤，完整草稿仍可点击查看，最后的保存才展示审批摘要。失败、拒绝、草稿待保存、等待审批与已保存分别显示，提交执行请求不等于任务已经完成。读取中的草稿也会明确标记尚未生效。

保存预览使用审批前固定的完整定义，保存后的启停和下次执行时间来自当次结果；删除、立即执行和取消在既有参数准备阶段附带简短 `task_preview`。历史卡片只读取消息里已保存的数据，不再查询可能已经改名、修改或删除的当前任务，不新增数据库或历史快照存储。

工具只管理当前助手的任务；目标聊天和用户消息都校验所属助手及当前分支。更新提交任务 ID、`revision` 和要改动的字段，不再要求重写完整定义。
`definition` 未提供的字段沿用当前草稿值（首次编辑时来自已保存任务），`schedule` 内也只更新指定字段；数组整体替换，显式 `null` 清空可空字段，`enabled` 省略时保留当前启停状态。
只传 `schedule.timeMinutes` 或 `schedule.at` 时切换到对应单时间，并清空原来的多时间数组，避免旧数组覆盖新时间。
`get` 优先返回同版本的当前草稿，`list` 只列出正式任务。草稿步骤返回 `draft=true`，不能声称已经生效；最后必须等待草稿编辑完成，再单独调用 `save`，无需重传提示词或配置。
最终配置在审批前由应用从草稿解析并固定到工具参数中，批准、拒绝、重启后继续都复用既有审批与聊天消息机制；审批期间正式配置发生变化仍沿用原有版本校验，要求重新读取。
创建使用 `options` 返回的任务 UUID，手动执行使用请求 UUID，重放不会创建重复任务或重复运行。

提示词局部修改直接复用 `workspace_edit_file` 的 `replaceText`：在 `update` 中传 `old_text`、`new_text` 和可选的 `replace_all`。
替换一段现有文字即可修改；在 `new_text` 中保留定位文字并增加内容即可插入；`new_text=""` 删除所选片段。
匹配方式和多处匹配处理与工作区一致，不再实现另一套文本编辑器；同一次调用不要同时提交 `definition.prompt` 全量替换和局部编辑。
例如只改时间用 `definition={"schedule":{"timesMinutes":[600,1080]}}`，只改提示词的一句话用 `old_text="英文汇报"`、`new_text="中文汇报"`，都无需重写其余提示词、模型或执行设置。
完整替换提示词仍可直接设置 `definition.prompt`。任务添加和删除继续使用 `create/delete`，不需要绑定工作区或操作真实文件。
草稿新配置保存在既有工具结果 metadata 中，不给模型反复回传全文，不保存旧提示词对比；保存成功后用同一消息机制标记草稿已应用。
最终审批预览直接读取固定后的完整配置，保存继续走原有仓库、版本校验及排程逻辑；未批准前正式任务保持原样。不新增数据库、文件存储或编辑框架。

`definition.resetContextBeforeRun` 控制继续聊天的执行前清空，默认 `false`，其他执行方式不能开启。AI 只能按用户明确要求开启，审批预览明确展示会删除旧记录。配置复用本分支任务定义 JSON 和运行快照，不新增旧 c 分支的表或运行状态字段。

AI 创建多时间任务时也只建立一个任务：例如每天 10:00、18:00 使用 `schedule.timesMinutes=[600,1080]`，每周排程另指定 `weekdays`；指定日期当天的多个时刻放入 `schedule.atTimes`。非空数组优先于对应的单时间字段。已有任务仅修改提示词或调整时间数组的顺序、重复项时，保留尚未消耗的执行时间。

定时执行期间，工具声明和执行入口同时限制为只读查询，禁止递归创建、修改或触发另一任务。普通即时请求不视为定时管理请求。

## 验证范围

JVM 测试覆盖日期范围、周排程、间隔锚点、夏令时、助手与消息分支校验、快照序列化、会话抢占规则，以及编辑时保留待执行时间、最新启停状态和运行快照。执行前清空测试覆盖旧消息、分支、压缩检查点和建议的移除，聊天配置保留，重复执行只保留最新一轮，以及开关和运行快照的持久化。Room 设备测试覆盖活动占用唯一性、审批占用、运行历史清理和级联删除；无连接设备时只能编译，不能当作已执行。

发布前应在手机验证精确闹钟授权与撤销、锁屏到期、重启、时区变化、后台限制、工具审批后恢复、取消及通知行为。
