# Phone Use（无障碍）

使用 [RikkaHub 上游 Phone Use](https://github.com/rikkahub/rikkahub/commit/25b70392adf7abd1c7742d46fd63c22f22a712ce) 的工具、无障碍服务和悬浮窗联动。来源与必要适配见 [源码来源](phone-control-sources.md)。

## 开启

仅 GitHub 渠道、Android 11 及以上提供。先在「设置 → 偏好设置 → 通知」开启后台悬浮窗并授权，再在助手「本地工具」开启 Phone Use；系统无障碍设置中的服务名为 **RikkaPlus Phone Use**。若服务尚未开启，工具开关会带用户进入系统设置。

从旧手机操作升级后需要重新开启这个新服务，旧组件及「扩展管理 → 手机操作」设置页已移除。助手中的工具选择继续保存在现有设置中，不新增数据库或表结构。

## 工具

模型使用一个 `phone_use` 工具，以 `action` 选择操作。

| action | 用途 |
| --- | --- |
| `observe` | 读取可见应用窗口及获得焦点的系统窗口，返回最多 150 个精简元素。 |
| `screenshot` | 返回 JPEG 聊天图片，最长边不超过 1568 像素；系统限频时按上游方式等待并重试一次。 |
| `tap` / `long_press` | 按最近元素列表的 `element` 编号，或 `x/y` 坐标操作。 |
| `swipe` | 从 `x/y` 滑动到 `to_x/to_y`。 |
| `scroll` | 按方向滚动，可指定 `element` 作为滑动区域。 |
| `type` | 设置输入框文字，可使用 `submit=true` 调用输入法回车。 |
| `press` | 返回、主页、最近任务、通知栏或回车。 |
| `open_app` / `list_apps` | 按名称或包名打开应用，或列出可启动应用。 |
| `wait` | 等待界面加载后重新读屏。 |

坐标统一使用 0–1000 网格：`x = 图中横向位置 / 图片宽度 × 1000`，纵向同理。元素编号仅对应最近一次列表，布局变化后应重新观察。

## 上游行为

改变界面的操作完成后等待并自动返回新元素列表。截图及手势期间，后台悬浮窗临时透明并让出触摸，手势以无障碍覆盖层显示落点或轨迹；使用 Phone Use 的一轮结束后，悬浮窗自动展开。

聊天步骤按读屏、截图、点击、滑动、输入、打开应用等动作分别显示图标与标题，并带上元素编号、坐标、应用名等关键参数。中文离线提示包含开启系统自启动的建议；此提示不会自动修改系统设置。

沿用上游限制：必须开启后台悬浮窗及其权限；本应用在前台时不能读取或操作自身，可先打开其他应用或返回主页；上游名单中的支付和银行应用不可读取或操作，只能返回或退出。上游工具没有旧版逐动作审批开关，提示词要求在未经用户授权的不可逆操作前先询问。

自定义绘制界面、系统不暴露的节点、受保护画面及系统拒绝的手势仍可能失败。当前实现采用上游的固定动作等待和元素位置，不保证动态页面中的旧编号始终有效。

## 存储与验证

图片仍由现有 FilesManager 保存为聊天附件，工具记录沿用现有聊天存储。已删除旧框架、13 个旧工具、专用设置和审批适配、旧资源与测试；保留的 `phone_control` 仅是助手选择已有的序列化标识，实际执行工具为 `phone_use`。

验证包括上游工具与悬浮窗单元测试、助手设置持久化、GitHub/Play 两个渠道的编译及清单核对。没有连接 Android 设备时，不将这些检查当作手机读屏、截图或手势实测。
